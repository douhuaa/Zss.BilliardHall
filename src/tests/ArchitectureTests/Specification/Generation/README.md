# Architecture Test Generator

架构测试生成器 - 自动将 RuleSet 转换为 xUnit 测试代码

## 概述

`ArchitectureTestGenerator` 是一个用于自动生成架构测试代码的工具。它接收 `ArchitectureRuleSet` 对象作为输入，生成符合命名规范的 xUnit 测试类代码，支持 NetArchTest.Rules 框架。

## 核心组件

### 1. IArchitectureTestGenerator

测试生成器接口，定义了生成测试代码的契约。

```csharp
public interface IArchitectureTestGenerator
{
    GeneratedTestCode Generate(ArchitectureRuleSet ruleSet, TestGenerationOptions? options = null);
}
```

### 2. ArchitectureTestGenerator

接口的具体实现，负责将 RuleSet 转换为测试代码。

**生成策略**：
- 使用 Theory + MemberData 模式（参考 ADR-907 Auto_Tests）
- 为每个 Clause 生成测试数据
- 生成命名符合 `ADR-XXX_Rule_Clause` 规范的方法
- 包含 NetArchTest 断言示例
- 提供可扩展的执行绑定点

### 3. TestGenerationOptions

配置生成选项的类。

**可配置项**：
- `Namespace`: 生成的测试类命名空间（默认：`Zss.BilliardHall.Tests.ArchitectureTests.Generated`）
- `TestClassSuffix`: 测试类名后缀（默认：`_Tests`）
- `IncludeComments`: 是否包含详细注释（默认：`true`）
- `IncludeExampleImplementation`: 是否包含示例实现（默认：`true`）
- `UseTheoryPattern`: 是否使用 Theory 模式（默认：`true`）
- `IndentString`: 代码缩进字符串（默认：4个空格）

### 4. GeneratedTestCode

生成的测试代码结果模型。

```csharp
public sealed record GeneratedTestCode(
    string ClassName,
    string SourceCode,
    string Namespace,
    int TestMethodCount
);
```

## 辅助工具类（Feature 内部实现）

> **注意**：这些工具类是 Generation Feature 的内部实现，专门用于代码生成场景。
> 根据垂直切片原则，它们不应被其他 Feature 直接引用。

### CSharpIdentifierHelper

C# 标识符辅助工具，用于清理和规范化标识符。

**主要方法**：
- `ToValidIdentifier(string input)`: 将字符串转换为有效的 C# 标识符
- `ToPascalCase(string input)`: 转换为 Pascal 命名格式
- `IsValidIdentifier(string input)`: 验证标识符有效性

**使用场景**：
- 从 Clause 描述生成方法名
- 清理特殊字符和非法标识符
- 规范化命名格式

### CodeGenerationHelper

代码生成辅助工具，用于格式化和构建代码。

**主要方法**：
- `NormalizeNewlines(string input)`: 规范化行尾为 LF
- `Indent(string text, int level)`: 添加缩进
- `BuildCodeBlock(params string[] lines)`: 构建代码块
- `BuildXmlDocComment(string summary)`: 生成 XML 文档注释
- `EscapeStringLiteral(string input)`: 转义字符串字面量
- `BuildNamespaceDeclaration(string ns)`: 构建命名空间声明
- `BuildUsingStatements(params string[] namespaces)`: 构建 using 语句

**使用场景**：
- 生成格式化的 C# 代码
- 构建 XML 文档注释
- 行尾标准化（避免跨平台差异）

## 使用示例

### 基本用法

```csharp
// 创建生成器实例
var generator = new ArchitectureTestGenerator();

// 获取 RuleSet
var ruleSet = RuleSetRegistry.GetStrict(907);

// 生成测试代码
var result = generator.Generate(ruleSet);

// 输出结果
Console.WriteLine($"类名: {result.ClassName}");
Console.WriteLine($"命名空间: {result.Namespace}");
Console.WriteLine($"测试方法数: {result.TestMethodCount}");
Console.WriteLine($"源代码:\n{result.SourceCode}");
```

### 自定义选项

```csharp
var generator = new ArchitectureTestGenerator();
var ruleSet = RuleSetRegistry.GetStrict(907);

// 自定义生成选项
var options = new TestGenerationOptions
{
    Namespace = "MyProject.Tests.Architecture",
    TestClassSuffix = "_ArchTests",
    IncludeComments = true,
    IncludeExampleImplementation = true,
    UseTheoryPattern = true
};

var result = generator.Generate(ruleSet, options);
```

### 生成不包含示例实现的代码

```csharp
var generator = new ArchitectureTestGenerator();
var ruleSet = RuleSetRegistry.GetStrict(907);

var options = new TestGenerationOptions
{
    IncludeExampleImplementation = false
};

var result = generator.Generate(ruleSet, options);
// 生成的代码将包含 TODO 注释而不是示例实现
```

## 生成的代码结构

生成的测试类包含以下部分：

1. **命名空间声明**
   ```csharp
   namespace Zss.BilliardHall.Tests.ArchitectureTests.Generated;
   ```

2. **类文档注释**
   - ADR 编号
   - 规则和条款数量
   - 使用说明

3. **测试数据提供器**
   ```csharp
   public static IEnumerable<object[]> GetAllClausesData()
   {
       yield return new object[] { ruleId, clauseId, safeName, displayName };
       // ...
   }
   ```

4. **Theory 测试方法**
   ```csharp
   [Theory(DisplayName = "ADR-XXX 条款执行测试")]
   [MemberData(nameof(GetAllClausesData))]
   public void ExecuteClause(int ruleId, int clauseId, string safeName, string displayName)
   {
       // 测试实现
   }
   ```

5. **示例实现**（可选）
   - RuleSetRegistry 访问
   - 执行类型 switch 语句
   - NetArchTest 断言示例

## 命名规范

### 测试类命名

格式：`Adr{编号:D3}AutoGenerated{后缀}`

示例：
- `Adr907AutoGenerated_Tests`
- `Adr001AutoGenerated_ArchTests`

### 测试方法命名

Theory 模式：`ExecuteClause(int ruleId, int clauseId, string safeName, string displayName)`

Fact 模式：`Rule{RuleId}_Clause{ClauseId}_{SafeName}()`

示例：
- `Rule1_Clause1_唯一执法形式()`
- `Rule2_Clause3_一对一映射()`

## 设计原则

1. **最小化手工编写**：减少重复性的测试代码编写工作
2. **规范化命名**：确保生成的代码符合项目命名约定
3. **可扩展性**：支持通过选项自定义生成行为
4. **可读性**：生成的代码包含详细注释和使用说明
5. **一致性**：使用统一的代码格式和行尾标准

## 局限性

1. **不支持复杂的测试逻辑**：生成的代码提供框架和示例，具体的测试断言需要手工实现
2. **需要 RuleSet 完整性**：每个 Rule 必须至少有一个 Clause
3. **命名冲突处理**：如果条款名称包含特殊字符，会被转换为下划线
